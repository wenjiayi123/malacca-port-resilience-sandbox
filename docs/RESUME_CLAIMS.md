# 简历主张与代码证据

更新日期：2026-07-24

## 可直接使用的版本

### 5.【工程4】马六甲海峡港航网络韧性数字孪生沙盘推演系统（独立全栈自研）

[系统演示] / [GitHub 源码]

面向国际航道突发事件与拥堵治理的宏微观一体化推演平台，覆盖港口/航道态势、拥堵与延误传播、
风险预警、碳排估算、韧性评估和调度策略对比；支持同页内嵌 Godot Web 单船仿真视窗，并通过
标准化请求与结果合同完成微观验证结果回写。

▸ **算法工程**：实现 Q-Learning、SARSA、Expected SARSA、Dyna-Q 四种表格型强化学习算法及
MPC 控制基线，采用 70%/15%/15% 时间切分、训练段容量代理校准、验证前段超参数调节、验证后段
算法选优和最终测试封存，训练过程无渲染，完成后再生成留出回放轨迹。

▸ **离线验证价值**：基于 1995—2026 年 377 条 MPA 月度到港记录并对齐 ERA5 海面风场，完成
4 种 RL × 3 组超参数 × 3 个随机种子训练及 MPC 同环境留出评测；在 2021-09—2026-05 的
57 个月封存闭环回放中，三步 MPC 相对“保持计划”基线将模型延误与有效拥堵压力分别降低
66.00%/66.27%，吞吐保持率 99.03%、逐步期望安全风险率 3.67%，期末递延积压 493.1 艘；
全部指标通过预声明离线引用门禁（公开聚合数据与动作参数假设下的模型结果，非港口实测 KPI）。

▸ **技术栈**：React 19 + TypeScript + Vite + Node.js Job API + 表格型 RL/MPC + Godot Web +
SHA-256 检查点与 JSON 数据合同。

## 指标边界

- 上述百分比来自真实执行的仓库训练/评估代码，但证据等级是**公开月度数据上的离线模型回放**，
  不是港口现场业务 KPI、生产节省或认证结论。
- 不应继续写“网络韧性评估模型准确率达 89%”。仓库没有真实韧性标签、预测目标和准确率定义；
  Web 端网络韧性指数是由节点压力、航路风险、恢复能力和事件压力计算的派生评分。
- 六维表格状态显式包含队列/能力、延误、碳指数、递延积压/能力、需求趋势和天气风险，避免错峰
  动作把需求移出可见队列后形成非马尔可夫状态；有效拥堵同时计入递延积压。
- 确定性评测使用期望违规概率而不是固定随机数生成“零事故”；五种动作的错峰、分流、能力与碳
  系数均标为情景假设，未冒充现场干预的因果估计。
- 默认数据风速覆盖率 100%，但容量、完整风浪能见度向量和安全字段覆盖率为 0；容量使用只由
  训练段校准的经验代理，天气压力测试中的浪高/能见度扰动是合成值。
- 验证选优 RL 在封存闭环回放中的延误与碳指标跨种子不稳定，简历不引用其收益；主指标引用同环境
  的确定性 MPC 控制基线，并保留完整 RL 结果供审查。
- “适配中远全球化航线布局战略”属于求职定位，不是代码或数据能证明的已落地成果。建议改成
  “面向全球干线港航网络的应急决策与拥堵治理场景”。
- Godot Web 视窗和 Web 侧 `postMessage` 请求/结果监听已经实现；当前可复现的结果闭环仍以
  JSON 导入/回写为主，不能描述为已完成生产级自动双向控制。
- 当前已建立通过发布门禁的本地基线提交，但尚未配置或推送 GitHub 远端；在仓库实际公开、
  可下载并由干净环境按 README 复现前，不应把 `[GitHub 源码]` 链接描述为已发布成果。

## 证据文件

- `server/rlTrainingEngine.ts`：环境、奖励、四种 RL、MPC、调参、验证选优与最终测试。
- `server/portTrainingDataset.ts`：CSV/JSON 数据合同、训练段容量代理和时间隔离。
- `reports/rl-benchmark-balanced-resilience.json`：机器可读多随机种子指标。
- `reports/rl-benchmark-balanced-resilience.md`：简历指标摘要与证据等级。
- `scripts/rl/verifyBenchmarkReport.ts`：复核数据指纹、核心代码指纹、全部算法/场景和数值完整性。
- `src/App.tsx`：网络韧性派生评分、RL UI、Godot Web 视窗及请求/结果消息合同。
- `tests/rlTrainingEngine.test.ts`：数据泄漏、目标权重、参数更新、留出测试与推理验证。
