# 控制算法模型卡

版本：`core-operations-rl.v1`（保留 `dataset-calibrated-port-control.v2` 历史基线）
用途：港口十域联合建议控制与历史控制基线的研究型、离线、可审计比较。

## 方法

仓库实现 Q-Learning、SARSA、Expected SARSA、Dyna-Q 四种表格型强化学习算法，以及模型预测
控制（MPC）基线。四种 RL 执行真实价值函数更新；Dyna-Q 额外执行模型规划回放；MPC 只做需求
模型辨识和滚动优化，不计作 RL。

当前主运行链另实现因子化线性 Q 与因子化线性 Dyna-Q。十个价值函数动作头共享 47 维观测，
分别覆盖到港、泊位岸桥、堆场闸口、水平运输、航道引拖、岸电储能、冷藏箱与楼宇负荷、设备维护、
海铁水水联运和扰动恢复。每个动作头从三个有界选项中选择，低种子一致性动作头单独回退保持计划，
而不是让一次弃权取消其他业务域。

## 数据与选择协议

- 数据按时间约 70%/15%/15% 划分为训练、验证、最终测试。
- 所有参数更新和 MPC 辨识只读训练段。
- 缺少实测能力时使用训练段到港量 P90 服务包络，不用验证/测试需求反推容量。
- 公开聚合环境限定单步错峰≤2%、分流≤1%、短时能力增益≤2%；常态负荷不足时 MPC 保持计划。
- 每种 RL 的超参数只由验证前段选择；五种方法的默认策略只由验证后段选择。
- 最终测试段仅在训练完成后由显式评估接口读取，生成可渲染 trace。
- 检查点保存随机种子、参数、港口 ID、数据指纹、三段范围、质量摘要、五种策略和 SHA-256。
- `pnpm benchmark:rl` 在多个随机种子上输出全部五种方法的留出结果；报告同时绑定训练引擎、数据
  加载器、目标预设、基准脚本、包清单和锁文件的 SHA-256，可用 `pnpm benchmark:rl:verify` 复核。
- 确定性 MPC 的跨种子零方差不作为稳定性证据；最终测试另切三个连续时间块分别冷启动回放。
- 独立的 INFORE Piraeus AIS 包处理 371,585 条原始消息并生成 1,440 条分钟记录，以同一五方法、
  多随机种子和时间留出协议做外部规模验证。它只有 24 小时，不能替代长期需求或现场运行证据。
- `terminal-operations.v2` 定义真实港口接入所需的 37 项运行字段。只有来源授权、字段覆盖、单位、
  时区和质量门禁通过后，适配器才允许将数据投影到现有六维控制环境。
- `core-operations-rl.v1` 使用 47 维共享张量、10 个并行动作头、14 项奖励和 13 项硬约束；比较两种
  因子化算法、两组超参数、五个随机种子与 180/360 两级课程。验证集先选型，最终时序测试保持封存。
- 冠军 `factorized-linear-dyna-q / curriculum-360` 的离线封存门禁通过，完整失败候选、五种子权重、
  源文件 SHA-256、配对反事实和权威边界保存在 `reports/core-operations-rl-champion-v1.json`。

## 预期用途

- 教学、算法复现、公开数据研究、港口适配器开发和离线方案比较。
- 在接入方自己的历史 TOS/VTS/AIS/气象数据上开展离线验证。
- 以场景配置复用马六甲或上海拓扑；场景背景与训练数据、实时快照和生产授权相互独立。

## 禁止用途

- 不得直接控制 VTS、TOS、船舶、泊位、引航或拖轮设备。
- 不得把 MPA 月度样例的结果解释为泊位级实时调度效果。
- 不得把模型的碳排、拥堵、延误或韧性输出描述为实测或认证指标。
- 未经过安全约束、港口规则校核和人工批准，不得用于生产下发。

## 已知限制

- 默认公开数据为月度聚合，到港服务能力使用训练段统计代理；ERA5 风速覆盖完整，但浪高、能见度和
  安全字段缺失，因此完整气象向量覆盖率仍为 0。
- Piraeus AIS 外部包只有单接收站附近 24 小时匿名航迹，没有 GT、泊位能力、天气、安全、港口
  调用事件或动作结果。其四种 RL 基线在留出段均产生负向延误/拥堵结果，报告不做选择性隐藏。
- 历史表格型基线仍离散化连续过程；新的十域主链使用连续特征的线性价值函数，但未实现深度强化
  学习、多智能体博弈或现场数字孪生标定。多随机种子置信区间不能替代现场业务验收。
- 十域主链已直接读取泊位、岸桥、堆场、闸口、水平运输、航道、引拖、能源、冷藏、维护、联运和
  恢复字段；默认数据中只有公开到港与气象锚点，其他字段仍是明确标注的工程增强值。
- 压力/天气泛化测试是对最终测试记录施加文档化扰动，不是新的现场观测。
- 当前保守压力诊断只施加到港 +5% 与临时能力 −2%；基线负担过小时，相对下降百分比自动失去
  摘要引用资格，报告仅保留绝对前后值。
- 单实例检查点适合参考部署；多实例应使用任务数据库、对象存储、队列和模型审批系统。

## 复现与验收

运行 `pnpm benchmark:core-operations && pnpm benchmark:core-operations:verify` 可重训并核验十域冠军；
运行 `pnpm release:check` 会同时覆盖历史模型与当前主链。测试会验证三段时间隔离、真实参数更新、五策略存在、最终测试时间戳、
多港口选择、重复时间戳拒绝、运行清单失败关闭、检查点摘要、新进程恢复和两个报告的证据完整性。
任何指标对比都应同时报告数据来源、许可、数据指纹、港口 ID、随机种子、算法参数和运行版本。
