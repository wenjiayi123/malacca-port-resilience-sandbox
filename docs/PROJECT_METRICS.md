# 项目指标与适用范围

更新日期：2026-08-31

## 项目摘要

### 5.【工程4】马六甲海峡港航网络韧性数字孪生沙盘推演系统（独立全栈自研）

[系统演示] / [GitHub 源码]

面向国际航道突发事件与拥堵治理的宏微观一体化推演平台，覆盖港口/航道态势、拥堵与延误传播、
风险预警、碳排估算、韧性评估和调度策略对比；支持同页内嵌 Godot Web 单船仿真视窗，并通过
标准化请求与结果合同完成微观验证结果回写。

▸ **业务系统价值**：自主研发宏观港航网络与微观单船验证一体化推演平台，覆盖港口节点监控、
航道拥堵热力、突发事件注入、风险预警、碳排核算和 AI 调度策略对比，并以 Godot Web 消息契约
回写单船验证轨迹；训练、策略测试、前端回放、人工确认和审计报告形成完整闭环。

▸ **业务价值**：面向港航拥堵治理与韧性决策，构建“长期需求—高频轨迹—算法验证—真实港口
接入”一体化证据链：主基准处理 Maritime and Port Authority of Singapore
`Vessel Arrivals (>75 GT) and Shipping Tonnage` 与 Open-Meteo ERA5 风场，覆盖
**31 年、377 个月、统计口径累计 4,064,858 艘次到港量**；外部规模验证处理 Zenodo/INFORE
`10.5281/zenodo.3754481` 的 **371,585 条原始 Piraeus AIS 消息**并生成 **1,440 个分钟级
船舶活动窗口**。在 263/57/57 严格时序隔离下，统一评测 Q-Learning、SARSA、Expected SARSA、
Dyna-Q 与三步 MPC，完成 **21,600 个 RL episodes**（4 算法 × 3 参数组 × 3 随机种子 × 600），
并由封存测试阻止稳定性不足的 RL 策略被包装为业务收益。重校准后，常态回放中 MPC 在
**96.49%** 时段保持原计划；在明确限定的“到港 +5% / 临时能力 −2%”离线压力诊断中，将代理
延误从 **0.344h 降至 0.110h（绝对减少 14.0 分钟）**、有效拥堵压力从 **1.435% 降至
0.468%（绝对减少 0.967 个百分点）**，同时保持 **99.715% 吞吐**和 **3.734% 逐步期望安全
风险**。系统因小分母主动禁用约 68% 的相对改善表述，并以 `terminal-operations.v2` 固化
**37 项港口运行字段**、数据质量与失败关闭门禁；获得授权 TOS/VTS/AIS、设备、气象和安全数据
后即可替换接入上海港或其他港口，马六甲仍为默认产品场景。

▸ **技术栈**：React 19 + TypeScript + Vite + Node.js Job API + 表格型 RL/MPC + Godot Web +
SHA-256 检查点与 JSON 数据合同。

▸ **当前全核心强化学习增量**：新增 47 维共享观测、10 个并行动作头、30 个有界选项、14 项奖励和
13 项硬约束的因子化线性强化学习闭环。五随机种子 `factorized-linear-dyna-q / curriculum-360`
通过验证与封存测试：综合奖励改善 95% 置信下界 0.02377，等待减少下界 0.081238 小时，能源成本
指数降低下界 0.600716%，峰值负载降低下界 1.326549 个百分点，碳强度降低下界 1.684997%，
十个动作域均实际参与且硬约束违规为 0。后端已实现联合推理、逐域弃权、安全投影、模拟双岗审批、
独立沙盘执行、幂等回执、回滚与审计哈希；上述数据是公开数据锚定的工程仿真配对反事实，不是现场
关键绩效指标或财务节省。

## 指标边界

- 上述前后值来自真实执行的仓库训练/评估代码，但证据等级是**公开月度数据上的离线压力诊断**，
  不是港口现场业务 KPI、生产节省或认证结论；66% 旧指标已降级为校准前历史对照。
- 不应继续写“网络韧性评估模型准确率达 89%”。仓库没有真实韧性标签、预测目标和准确率定义；
  Web 端网络韧性指数是由节点压力、航路风险、恢复能力和事件压力计算的派生评分。
- 六维表格状态显式包含队列/能力、延误、碳指数、递延积压/能力、需求趋势和天气风险，避免错峰
  动作把需求移出可见队列后形成非马尔可夫状态；有效拥堵同时计入递延积压。
- 确定性评测使用期望违规概率而不是固定随机数生成“零事故”；五种动作限定为单步错峰≤2%、
  分流≤1%、短时能力增益≤2%，均标为情景假设，未冒充现场干预的因果估计。
- 默认数据风速覆盖率 100%，但容量、完整风浪能见度向量和安全字段覆盖率为 0；容量使用只由
  训练段校准的经验代理，天气压力测试中的浪高/能见度扰动是合成值。
- 验证选优 RL 的常态封存回放会产生不必要干预，简历不引用其收益；确定性 MPC 不再用跨种子
  零方差包装稳定性，改为三个连续封存时间块冷启动诊断并保留完整结果。
- Piraeus AIS 外部比较中四种 RL 的延误/拥堵均值全部恶化，MPC 在代理环境中改善；报告保留这组
  负结果，不用数据量掩盖缺少现场能力、动作结果和跨日泛化的事实。
- 上海场景中的公开年吞吐、洋山占比、海铁联运和泊位利用率只用于背景基线；没有授权清单时，
  队列、船舶、现场效率和“已生产接入”状态均失败关闭。
- “适配中远全球化航线布局战略”属于求职定位，不是代码或数据能证明的已落地成果。建议改成
  “面向全球干线港航网络的应急决策与拥堵治理场景”。
- Godot Web 视窗和 Web 侧 `postMessage` 请求/结果监听已经实现；当前可复现的结果闭环仍以
  JSON 导入/回写为主，不能描述为已完成生产级自动双向控制。
- GitHub 公开远端为 `wenjiayi123/malacca-port-resilience-sandbox`；每次发布仍必须由干净检出
  执行 `pnpm install --frozen-lockfile && pnpm release:check`，通过后才可引用对应提交指标。

## 复现资料

- `server/rlTrainingEngine.ts`：环境、奖励、四种 RL、MPC、调参、验证选优与最终测试。
- `server/coreOperationsRlEngine.ts`：十域因子化 Q / Dyna-Q、逐域动作屏蔽、训练和封存价值门禁。
- `server/coreOperationsRlService.ts`：权威运行快照到 47 维张量、五种子集成、逐域弃权和业务投影。
- `reports/core-operations-rl-champion-v1.json`：十域冠军、全部候选、权重、指纹和配对反事实证据。
- `server/portTrainingDataset.ts`：CSV/JSON 数据合同、训练段容量代理和时间隔离。
- `shared/rlOperationalCalibration.ts`：P90 容量代理、温和压力边界和保守动作上限。
- `reports/rl-benchmark-balanced-resilience-calibrated-v2.json`：机器可读多随机种子与三时间块指标。
- `reports/rl-benchmark-balanced-resilience-calibrated-v2.md`：当前简历指标摘要与证据等级。
- `reports/rl-benchmark-balanced-resilience.md`：校准前 66% 历史报告，仅用于差异审计。
- `reports/public-dataset-credibility-comparison.json`：Piraeus AIS 高频外部比较和负结果。
- `scripts/data/sync_infore_ais.mjs`：公开 AIS 下载、MD5 校验、清洗和分钟聚合。
- `scripts/rl/verifyBenchmarkReport.ts`：复核数据指纹、核心代码指纹、全部算法/场景和数值完整性。
- `shared/portOperationalContract.ts`：上海接入字段、观测、动作证据和目标门禁。
- `docs/SHANGHAI_PORT_LANDING.md`：现实因素、字段映射、公开来源和生产接入步骤。
- `src/App.tsx`：网络韧性派生评分、RL UI、Godot Web 视窗及请求/结果消息合同。
- `tests/rlTrainingEngine.test.ts`：数据泄漏、目标权重、参数更新、留出测试与推理验证。
