# 港航关系图与信息说明改版

日期：2026-10-24

## 原问题

- 港口、国家、英文标签和样船延误徽标在缩小后叠在画面中央。
- 历史装饰路径不能清楚表达场景中配置的起点、终点和方向。
- 只有线条和数字，缺少航段名称、航道、状态、指标单位及后续操作。
- 场景范围内港口数量与实际绘制节点数、模拟流量与代表样船数没有说明口径。

## 本次实现

- 默认采用港航关系图，按现有 `originPortId` / `destinationPortId` 连接港口，R 编号与航段清单一一对应。方向箭头放进编号牌，短航段也可读。
- 港口卡片标注所属国家、名称、排队和状态；国家大字、重复英文及样船徽标退出默认图。
- 主干、港间接续、分道通航有颜色与线型双重区分；支持类型/关注筛选、港口和 R 编号搜索、空结果恢复、样船显示开关和重置。
- 港口详情显示排队、等待、拥堵、泊位利用率、关联航段和样船。航段详情显示起讫港、航道、状态、模拟流量、延误、航速、拥堵及关联样船。
- 样船详情说明演示身份和延误组成；明确其数量与模拟流量不同口径。
- 关丹、巴淡保留为扩展观察节点，明确当前场景没有绑定起讫航段；缺失端点的航段不猜测连线。
- 点选用于浏览；明确点击验证或韧性按钮后，才进入原有业务入口。
- 原仿真分析图层作为独立标签保留，压缩标签并补全延误单位。
- Belawan 在展示层使用运营商官方英文港名，未改动历史场景数据和训练资料。名称依据：https://pelindo.co.id/port/pelabuhan-belawan 。
- 演示开场改为读取新关系图，分析视角阶段先打开真实分析图层。
- 补查发现原演示没有核对策略准入结果，却在保留事件时直接生成单船请求，会被原生前置门阻止。新增“检查点推理与准入结果”及“明确重置并建立独立无事件样例”两步，演示由 28 步补全为 30 步。拒绝策略保留未采用状态，微观速览明确属于独立样例，没有放宽原门禁。
