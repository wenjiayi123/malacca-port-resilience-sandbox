# 港航基础数据模型

## 代码位置

- 类型定义：`src/types/sandbox.ts`
- 当前示例场景：`src/data/malaccaScenario.ts`
- UI 消费入口：`src/App.tsx`

## 核心模型

### MalaccaScenario

主场景对象，聚合当前沙盘推演所需的所有基础数据：

- `metrics`：态势总览首页核心指标，包含实时船舶总数、今日过境船舶、吞吐量、碳排放和网络韧性指数。
- `overview`：港口、航道、锚地和监测船舶总览。
- `vesselTypeStats`：船型分类统计。
- `ports`：港口节点。
- `channels`：航道状态。
- `routeOverlays`：地图上的 SVG 航道线和航道流推演指标。
- `vesselMarkers`：地图上的动态船舶点位。
- `weather`：气象与海况。
- `riskAlerts`：风险预警。
- `carbon`：碳排放监测。
- `congestionHeatmap`：拥堵热力图基础数据。
- `strategies`：绿色调度策略。
- `eventLog`：底部事件流，沙盘推演控制中的事件注入会在运行时追加到该事件流前部展示。

### MetricCard

态势总览首页指标字段包括：

- 指标 ID、中文名称、主数值和单位。
- 指标口径说明，用于解释数值来源或统计范围。
- 变化状态文案，用于展示较上一时段、较昨日或预测值。
- 状态色，用于区分正常、预警和风险指标。

### NetworkOverview

左侧港航网络总览字段包括：

- 港口数量。
- 航道数量。
- 锚地数量。
- 当前监测船舶总数。
- 小地图中的港口点位和航道线分别复用 `ports` 与 `routeOverlays` 数据。

### VesselTypeStat

左侧船舶态势模块字段包括：

- 船型分类，包括货船、油轮、集装箱船、散货船和其他船型。
- 各船型数量。
- 各船型占监测船舶总数的比例。
- 分类列表、占比条和环形图共用该数据源。

### PortNode

港口节点字段包括：

- 港口名称、英文名、所属国家、港口等级。
- 地图屏幕坐标和真实经纬度坐标。
- 关联航道 ID，用于后续把港口排队、航道延误和船流仿真结果打通。
- 船舶数量、拥堵度、泊位利用率、排队船舶数和平均等待小时数。
- 日吞吐量、泊位数量、锚地数量、单位货物碳强度和韧性评估权重。
- 当前状态和状态色。
- 右侧“关键节点监控”模块使用港口名称、船舶数量、拥堵度和状态色展示重点港口运行表格。
- 地图“港口拥堵推演”浮层使用船舶数量、排队船舶、泊位数量、泊位利用率和平均等待小时数派生到港、排队、靠泊、装卸、离港五阶段推演结果。

### PortCongestionSimulation

港口拥堵推演派生结果包括：

- 港口 ID 和港口名称。
- 到港船舶数、排队船舶数、靠泊船舶数、装卸船舶数、离港船舶数。
- 预计等待小时数。
- 拥堵分值。
- 拥堵等级，包括低拥堵、中拥堵、高拥堵和严重拥堵。
- 状态色，用于地图推演浮层和等级标识。

### ChannelStatus

航道状态字段包括：

- 航道 ID、名称、航道类型。
- 通航状态、状态色。
- 拥堵度和延误分钟数。
- 左侧“航道通航状态”模块使用这些字段展示 6 条核心航道的状态徽标、延误和拥堵进度条。

### RouteOverlay

航道流字段包括：

- 航线 ID、名称、类型和状态色。
- 关联航道 ID、起点港口 ID、终点港口 ID。
- SVG 航道路径。
- 日船舶流量、平均航速、延误分钟数、碳排放量和动画周期。

### VesselMarker

船舶点位字段包括：

- 船舶 ID、船名、IMO 编号和船型。
- 地图坐标。
- 关联航道流 ID、目标港口 ID 和当前进度。
- 航速、航向和所属航道。
- 单船小时碳排放和动画延迟。
- 地图船舶延误标签和“船舶延误推演”表格会结合 `VesselMarker`、`RouteOverlay`、`ChannelStatus`、`WeatherSeaState` 和 `PortCongestionSimulation` 派生延误结果。

### VesselDelaySimulation

船舶延误推演派生结果包括：

- 船舶 ID、船名、航线名称和目的港名称。
- 总延误分钟数。
- 拥堵延误、天气延误、航速延误和航道风险延误。
- 主导延误因子。
- 状态色，用于地图动态船舶延误标签和延误排行表。

### VesselEmissionSimulation

燃油与碳排核算派生结果包括：

- 船舶 ID、船名、船型和航线名称。
- 航程、当前航速和等待时间。
- 估算燃油消耗。
- 估算碳排放。
- 基准碳排放。
- 较基准碳排变化比例。
- 状态色，用于“燃油与碳排核算”浮层和排行表。

### WeatherSeaState

气象与海况字段包括：

- 风速、风向。
- 气温、能见度。
- 浪高、流速、水温、气压。
- 右侧“气象与海况”模块使用这些字段展示指标卡和雷达/风向 UI。

### RiskAlert

风险预警字段包括：

- 风险 ID、名称和描述。
- 风险等级颜色，当前用于高风险和中风险的视觉区分。
- 影响区域。
- 预计影响。
- 左侧“风险预警”模块使用这些字段展示台风预警、海盗威胁、油污风险和拥堵预警。

### CarbonSnapshot

碳排数据字段包括：

- 今日碳排放。
- 较昨日变化。
- 小时级趋势数据。
- 趋势单位。
- 右侧“碳排放监测”模块使用这些字段展示今日总量、较昨日变化、趋势曲线、当前小时和峰值时段摘要。

### CongestionHeatmap

拥堵热力图字段包括：

- 热力图 ID、名称、低值标签和高值标签。
- `hotspots` 记录重点港口节点 ID 和热力强度。
- 右侧“航道拥堵热力图”模块会综合 `channels.congestionPercent`、`routeOverlays.vesselVolume`、`routeOverlays.delayMinutes` 和热点港口排队数据生成航道热线、港口热区、风险等级颜色和热点列表。

### GreenSchedulingStrategy

绿色调度策略字段包括：

- 策略类型。
- 作用对象。
- 预计延误降低比例。
- 预计碳排降低比例。
- 策略状态。
- 第 23 步已补齐低速航行、错峰进港、分流港口、优先靠泊和改道绕行五类策略种子数据。

### GreenStrategyComparison

绿色调度策略对比派生结果包括：

- 策略 ID、策略类型、名称、作用对象和策略状态。
- 受影响船舶数量。
- 预计延误削减分钟数。
- 预计节省燃油吨数。
- 预计碳减排吨数。
- 预计拥堵度降低比例。
- 综合推荐得分。
- 策略动作说明和状态色，用于地图“绿色调度策略对比”浮层。

### CriticalNodePressure

关键节点压力派生结果包括：

- 节点 ID 和节点名称。
- 关键节点压力分值。
- 结合港口韧性权重后的加权压力。
- 预计拥堵恢复小时数。
- 关联受影响航线数量。
- 状态色，用于“韧性评估模块”的高压节点排行。

### NetworkResilienceAssessment

韧性评估派生结果包括：

- 网络韧性指数。
- 拥堵恢复能力。
- 平均恢复小时数。
- 当前最高关键节点压力。
- 风险扩散范围比例。
- 受压节点数量。
- 受影响航线数量。
- 关键节点压力排行。
- 状态色，用于首页“网络韧性指数”和底部控制台“韧性评估”指标条。

### AiDecisionAdvice

规则型 AI 单条建议包括：

- 建议主题，包括拥堵原因、风险判断、调度建议和碳排优化建议。
- 建议标题。
- 建议摘要。
- 证据说明，用于悬停查看触发依据。
- 优先级分值，用于排序。
- 状态色，用于区分建议风险等级。

### AiDecisionRecommendation

AI 决策建议派生结果包括：

- 生成时间。
- 建议置信度。
- 主建议动作。
- 四类规则型建议列表。
- 综合状态色，用于底部控制台“规则 AI 决策建议”面板。

### EmergencyContingencyPlan

应急预案单项派生结果包括：

- 应急场景类型，包括事故封航、极端天气、港口瘫痪和能源管控。
- 预案名称。
- 影响区域。
- 触发条件。
- 主处置动作。
- 支撑动作。
- 预案准备度。
- 预计恢复小时数。
- 严重度分值。
- 状态色，用于底部控制台“应急预案”面板。

### EmergencyContingencyAssessment

应急预案综合评估包括：

- 生成时间。
- 当前激活场景。
- 当前激活预案名称。
- 平均准备度。
- 四类应急预案列表。
- 综合状态色，用于底部控制台“应急预案”面板。

### GodotIntegrationContract

Godot 对接契约用于连接 Web 宏观沙盘与 `/path/to/sailing-simulator` 微观验证层，字段包括：

- 协议版本。
- 桥接方式，首期使用 `file-json`，后续可扩展到 HTTP 或 WebSocket。
- Godot 工程路径。
- 请求文件路径和结果文件路径。
- Web 发往 Godot 的单船验证请求。
- Godot 回写 Web 的单船验证结果。

### GodotValidationRequest

Web 发往 Godot 的验证请求包括：

- 船舶 ID、船名、IMO 编号和船型。
- 起点港口和终点港口。
- 航线 ID、航道 ID、当前航段进度和初始航向。
- 航速配置，包括初始航速、目标航速、安全下限和安全上限。
- 风险事件列表，包括事故封航、极端天气、碰撞风险、港口瘫痪、能源管控和人工事件。
- 待验证调度策略 ID。
- 请求生成时间。

### GodotValidationResult

Godot 回写 Web 的验证结果包括：

- 请求 ID 和船舶 ID。
- 验证状态。
- 是否安全通过。
- 预计航行耗时。
- 综合风险等级。
- 推荐航速。
- 模拟时长。
- 是否抵达终点。
- 平均航速。
- 最小安全间距。
- 碰撞次数和搁浅次数。
- 已处理风险事件数。
- 相对 Web 预估的延误变化和碳排变化。
- Godot 已加载的微观验证场景摘要，包括航线点数量、风险区数量和临时障碍数量。
- 验证结论文本。
