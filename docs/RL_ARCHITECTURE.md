# RL 与控制基线架构

## 数据流

```text
CSV/JSON 或 MPA 样例
        │ 字段校验、排序、数据指纹
        ▼
时间切分：70% 训练段 ───── 15% 验证段 ───── 15% 最终测试段
        │                      │                    │
        ├─ Q-Learning          │ 前段：超参数调节    │
        ├─ SARSA               ├─ 五算法统一选优     │ 保持封存
        ├─ Expected SARSA      │                    │
        ├─ Dyna-Q              │ 后段：统一算法选优  │
        └─ MPC 需求模型辨识     │                    │
                    │          │                    │
                    └──检查点───┘        显式 /evaluate 后生成 trace
```

## 环境

状态由排队、递延积压、延误、碳强度、需求趋势和气象风险离散化构成。动作固定为：保持计划、
低碳航速平滑、错峰到港、邻港分流、泊位能力重配置。奖励是延误、拥堵、碳指数、安全违规、
韧性和吞吐服务率六项归一化权重的组合，并包含分流、扩容、递延成本。递延需求会在后续时段
释放，不会从环境中直接消失。

公开样例把 MPA 月度到港统计与同月 ERA5 风场对齐，但没有泊位实测能力、浪高、能见度和安全事件。
容量使用只由训练段校准的文档化统计代理；缺失的海况字段在普通回放中保持中性值，在天气压力测试
中使用显式、可检查的合成扰动。ERA5 风场不能替代港口气象站或法定航行气象资料。
接入生产数据时，显式字段会覆盖代理值。

## 算法真实性

- Q-Learning、SARSA、Expected SARSA：每个环境步执行一次对应的 Bellman 更新。
- Dyna-Q：除真实环境步更新外，对已见状态动作转移执行最多五次规划回放。
- MPC：不执行 RL 更新。训练段只用于一阶需求预测偏差与 RMSE 辨识；测试时枚举三步控制序列，
  每个验证/测试时刻重新选择第一步动作。

每种 RL 默认比较 3 组学习率/折扣因子候选；验证前段选超参数，验证后段选算法。任务响应分别报告
environment steps、parameter updates、executed episodes、visited states 和 elapsed time。MPC 的
`training.episodes` 固定为 0，避免把系统辨识伪装成 RL 训练。

## 训练与渲染分离

`POST /api/rl/jobs` 创建服务器异步任务。训练期间前端轮询 `GET /api/rl/jobs/:id`，只更新任务
状态；地图策略动画暂停。任务内部以验证段选优但不生成地图帧。任务完成后，显式调用
`POST /api/rl/jobs/:id/evaluate` 才读取最终测试段并返回 trace，前端
才按 trace 的真实步数推进回放进度。

## 检查点与在线推理

检查点默认写到 `.runtime/rl-jobs/<jobId>.json`，并可从
`GET /api/rl/jobs/:jobId/checkpoint` 下载。内容包含：

- 请求参数与随机种子；
- 数据源、切分范围与指纹；
- 五种方法的曲线和验证段统一评估结果；
- 四种 RL 的 Q 表或 MPC 模型参数。
- SHA-256 完整性摘要。

服务启动会扫描检查点，验证 SHA-256、数据指纹和港口 ID 后恢复已完成任务；不匹配或被篡改的
文件不会进入可推理任务表。`POST /api/rl/inference` 必须传入可恢复的已完成 `jobId`。多实例生产
部署仍建议把运行目录替换为对象存储与任务数据库，并为并发写入增加租约或队列。

单实例默认一次运行 1 个训练任务、最多等待 20 个任务，可用 `RL_MAX_CONCURRENT_JOBS` 与
`RL_MAX_QUEUED_JOBS` 调整；超过队列容量返回 503。检查点先写同目录临时文件，再原子改名，避免
进程中断留下被误恢复的半文件。

## 扩展到深度 RL

深度 RL 不是当前仓库已经训练好的能力。若新增 PPO/SAC/MAPPO，应实现相同 Job API，并真实
返回优化器更新、检查点、训练/测试隔离和资源遥测；在接入前不要在 UI 中展示这些算法或 GPU 指标。
