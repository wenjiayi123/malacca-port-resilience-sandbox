# 全核心业务强化学习运行闭环 v1

## 为什么需要这一增量版本

第三版港口全业务策略已经真实训练，能读取三十三维观测、选择十一个有界建议动作，并完成安全投影、种子一致性、置信度、数据质量、吞吐、堆场和碳排门禁。但它一次只选择一个业务动作，模拟审批后只生成证据报告；连续运行控制服务中的“强化学习检查点”还需要调用方另外传入动作。因此，训练证据真实，并不等于强化学习已经同时改变全部核心运行状态。

`core-operations-rl.v1` 是增量层，不删除或改写第三版策略、原四种表格型强化学习、模型预测控制、监管韧性策略、检查点、失败候选或历史报告。它解决两个问题：

1. 把单动作策略扩展为十个并行动作头，使同一决策时段可以同时形成到港、码头、能源和恢复计划；
2. 把联合计划接入独立沙盘执行器，经过模拟双岗审批后返回真实改变的后端状态、执行回执和追加式审计记录。

## 强化学习承担的十类核心职责

- 到港节奏：保持、低碳航速窗口、错峰到港；
- 泊位岸桥：保持、泊位重排、岸桥再平衡；
- 堆场闸口：保持、箱区再平衡、闸口预约平滑；
- 水平运输：保持、自动导引运输车再平衡、场内集卡池再平衡；
- 航道引拖：保持、引航拖轮优先、潮窗序列优化；
- 岸电储能：保持、岸电优先、储能削峰；
- 冷藏箱与楼宇柔性负荷：保持、冷藏箱负荷协同、楼宇需求响应；
- 设备维护：保持、预防维护窗口、故障恢复优先；
- 海铁水水联运：保持、海铁水水再平衡、邻港协同建议；
- 扰动恢复：保持、恢复能力调用、受控积压释放。

十个动作头共享四十七维观测和全局奖励，但分别保留动作白名单、适用性掩码和安全约束。因而一个动作头置信度不足时只回退该领域，不会把其他领域的有效策略一起丢弃。

## 明确不交给强化学习的事项

强化学习不得决定海事检查对象与结论、海关查验与正式放行、船舶交通服务航行指令、避碰与操舵、危险品联锁、上锁挂牌、紧急停止、身份鉴别、财务结算、生产下发和物理设备直接控制。这些职责继续属于主管机关、确定性优化与安全联锁、独立身份系统和人工批准执行器。

顶级系统不是让强化学习拥有全部最终权力，而是让强化学习在随机、跨时段、跨资源的联合优化中发挥作用，同时让硬约束和法定权力保持独立且可否决。

## 训练与价值归因

训练采用因子化线性价值函数控制和带规划回放的因子化线性价值函数控制。每个候选使用五个随机种子，先在训练时间段更新参数，再用验证时间段选择算法、参数和训练预算，最后只打开一次封存测试时间段。

业务价值使用配对反事实：强化学习和保守标准作业程序读取完全相同的记录、初始状态和四类扰动场景。报告保存综合奖励、等待、队列、能源成本、峰值负载、碳强度、设备维护积压、恢复积压、吞吐保持、冷藏箱服务、安全投影和硬约束差值及百分之九十五置信区间。只有全部门禁通过的候选才能成为离线冠军。

这能证明“同一离线工程仿真中，业务差值由策略选择造成”，不能证明马六甲港现场节省、财务收益或生产因果效果。公开月度到港与总吨位是数据锚点；泊位、设备、堆场、能源等缺失字段仍是工程增强变量，必须在现场由同步实测字段替换和标定。

## 运行执行链

运行路径如下：

1. 后端权威快照提供逐字段来源、时间、单位、质量和追踪编号；
2. 五随机种子策略集成对十个动作头同时推理；
3. 低一致性动作头单独回退保持计划；
4. 航道、潮窗、引拖、危险品、容量、储能、维护和通信安全投影器再次校验；
5. 两个本地测试角色模拟操作员与安全员审批；
6. 独立沙盘执行器从同一状态、同一随机种子和同一时刻分别推进“继续当前计划”和“执行新强化学习计划”；
7. 回执同时记录执行前后差值，以及新强化学习计划相对配对基线的关键绩效指标与领域差值，从而隔离该时段的自然演化；
8. 回滚和追加式审计链保留整个生命周期。

接口：

- `GET /api/rl/core/status`：读取冠军、封存测试门禁和权威边界；
- `POST /api/rl/core/infer`：从当前后端快照生成联合计划；
- `POST /api/rl/core/proposals/{proposalId}/approve`：模拟双岗审批；
- `POST /api/rl/core/proposals/{proposalId}/execute`：执行联合沙盘计划并返回回执；
- `POST /api/rl/core/proposals/{proposalId}/rollback`：回滚；
- `GET /api/rl/core/proposals/{proposalId}/report`：导出带审计哈希的完整报告。

## 生产边界

当前恒定保持：

```text
simulation_mode=true
live_data_verified=false
dispatch_allowed=false
production_authority=false
```

现场提升仍需要运营方授权的数据映射、单位与时区确认、实测标定、至少七百二十小时只读影子运行、独立运行技术联锁、真实多因素身份鉴别与角色权限、工厂验收、现场验收、用户验收、回滚演练以及物理执行适配器。本版本不伪造其中任何一项。
