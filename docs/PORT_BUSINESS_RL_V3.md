# 港口全业务强化学习与非强化学习控制 v3

## 结论与边界

原有控制器能真实训练 Q-Learning、SARSA、Expected SARSA、Dyna-Q，并以模型预测控制作非强化学习对照，但策略只直接读取六个聚合观测，动作只有保持计划、低碳航速、错峰到港、邻港分流和能力重配置。`terminal-operations.v2` 虽已收集泊位、岸桥、堆场、闸口、潮窗、引拖、岸电、能源成本和跨港字段，其中大部分没有进入同一奖励闭环。

`port-business-rl.v3` 是增量版本，不覆盖或删除原五算法、检查点、监管韧性模型和历史报告。它补齐八类可优化业务，同时把监管决定、安全联锁和生产权威留在强化学习之外。

当前冠军证据是 `OFFLINE_PUBLIC_ANCHORED_ENGINEERING_AUGMENTED_NOT_FIELD_KPI`：公开统计是真实锚点，补足字段是工程场景量。`simulation_mode=true`、`live_data_verified=false`、`dispatch_allowed=false`、`production_authority=false` 始终保持关闭。

## 业务覆盖

| 业务域 | v3 直接观测和优化 | 最终控制权 |
|---|---|---|
| 到港、排队和等待 | 需求压力、趋势、计划偏差、平均/尾部等待、积压 | 强化学习建议 + 人工批准 |
| 泊位和岸桥 | 泊位利用率/余量、岸桥效率/可用率、重排和再平衡 | 强化学习建议 + 确定性可行排程 |
| 堆场和闸口 | 堆场占用/余量、集卡周转、闸口压力、协同平滑 | 强化学习建议 + 容量联锁 |
| 通航和引拖 | 航道、潮窗、引航、拖轮、风浪流、能见度和危险品限制 | 规则联锁、船舶交通服务和调度员 |
| 岸电、能源和碳 | 岸电可用、碳强度、能源价格、岸电优先建议 | 能源容量规则 + 人工批准 |
| 海铁、水水和邻港 | 两类转运压力、网络余量、联运和邻港建议 | 港口协同协议及对方接受为外部事件 |
| 扰动恢复 | 能力损失、恢复积压、恢复能力调用 | 强化学习建议 + 应急预案 + 确定性排程 |
| 服务公平性 | 船型服务差距、引拖优先队列、公平性奖励 | 人工批准和公开服务规则 |

下列事项不得成为强化学习动作：海事检查选择与结论、海关查验与正式放行、船舶交通服务航行指令、避碰和操舵、危险品安全联锁、紧急停止、身份鉴别、生产下发、设备直接控制、财务结算和审计记账。

## 观测设计

策略实际接收 33 个归一化观测，不存在只展示而不进入价值函数的“装饰维度”。完整顺序和范围由 `shared/portBusinessRlContract.ts` 固定。

| 组 | 数量 | 关键内容 |
|---|---:|---|
| 到港与排队 | 8 | 到港/能力、趋势、ETA 偏差、船型尺度、队列、平均和 P95 等待、递延积压 |
| 泊位与岸桥 | 4 | 泊位利用率/余量、岸桥效率/可用率 |
| 堆场与闸口 | 4 | 堆场占用/余量、集卡周转、闸口压力 |
| 联运与网络 | 3 | 海铁压力、水水压力、可转移能力余量 |
| 通航与安全 | 6 | 航道、潮窗、引航、拖轮、综合风浪流风险、危险品限制 |
| 能源与碳 | 3 | 岸电可用、碳强度、能源价格 |
| 恢复与公平 | 3 | 能力损失、恢复积压、服务差距 |
| 可信度 | 2 | 预测不确定度、数据质量分数 |

数据质量和预测不确定度进入状态，使策略能够区分“业务压力高”和“证据不足”；生产适配器还应在分布外检测时退回确定性优化器或保持计划。

## 动作设计

11 个动作都是有界计划包或建议，不是物理指令：保持计划、低碳航速建议、错峰到港、泊位重排、岸桥再平衡、堆场闸口平滑、引航拖轮优先、岸电优先、联运再平衡、恢复能力调用、邻港协同建议。

动作在进入环境前依次通过：

1. 白名单；
2. 航道、潮窗、引拖、危险品、岸桥、堆场、岸电和转运能力硬约束；
3. 业务适用性掩码，避免在低压力时调用无关资源；
4. 一周期冷却，避免连续资源抖动；
5. 人工批准和生产授权门禁。当前第五步始终不允许生产下发。

## 奖励设计

标量奖励的十个分量权重总和为 1：服务水平 0.18、吞吐保持 0.14、延误 0.15、队列/积压 0.10、碳强度 0.08、能源成本 0.05、堆场闸口 0.08、公平性 0.07、扰动恢复 0.09、干预/切换成本 0.06。

硬安全约束不通过奖励权重换算，始终先于奖励执行。监管部门的检查或放行也不产生可被策略操纵的正奖励。

## 公开数据、补足方法和替换

训练锚点来自：

- [新加坡海事及港务管理局月度到港船舶与总吨位](https://data.gov.sg/collections/394/view)；
- [Open-Meteo Historical Weather API 的 ERA5 风场](https://open-meteo.com/en/docs/historical-weather-api)；
- 独立交通密度稳健性比较继续使用 [INFORE 匿名化 Piraeus AIS 数据](https://zenodo.org/records/3754481)，不把其活跃船舶密度改写成马六甲到港事件。

[世界银行集装箱港口绩效指数](https://www.worldbank.org/en/topic/transport/publication/cppi)只用于等待和在港时间的业务指标框架，[联合国贸易和发展会议班轮运输连接指数](https://unctadstat.unctad.org/insights/theme/246)只用于网络连接框架；两者的分数和排名都没有被伪装成训练标签。

随仓库公开快照的 377 个月度记录被确定性分解为 1,508 个周期；每个月的分解到港量严格回加到原公开月度总量。服务能力只用训练段第 90 百分位校准。泊位、岸桥、堆场、闸口、通航、岸电、能源价格、转运和公平性等缺失字段按有界工程关系生成，字段谱系统一标为 `engineering-derived`，不是测量值。

现场替换文件遵循 `docs/schemas/port-business-dataset-v3.schema.json`，至少 120 条、带时区时间戳、不得重复。设置：

```bash
PORT_BUSINESS_DATASET_PATH=/absolute/path/to/port-business-v3.json
```

加载器按时间执行 70% / 15% / 15% 训练、验证、封存测试切分。数据文件中的
`operator-authorized` 属于可篡改的自声明，加载器不会据此打开运行声明；它会降级为
`operator-supplied-unverified`。只有签名运营方网关、标定证据和现场验收门禁共同通过，才可在更外层
提升数据权威级别；这仍不等于生产调度授权。

## 真实训练和冠军门禁

四种带线性函数逼近的时序差分算法读取全部 33 维观测：Q-Learning、SARSA、Expected SARSA、Dyna-Q。Dyna-Q 还对真实采样的转移执行规划回放。每种算法比较两套学习率/折扣因子，使用 5 个随机种子和 260、520 两级课程；训练段更新参数，验证段选择算法、参数和课程，最终测试段在选择完成后一次性打开。

最终冠军为 `linear-dyna-q / curriculum-520`。封存测试由 5 个随机种子 × 4 个场景组成；等待和队列置信区间只在保持计划基线确有实质延误的需求激增与能力扰动场景上计算。业务门禁同时要求奖励、队列、吞吐、碳、公平性、堆场、闸口、干预率、动作切换和硬安全约束通过。结果见 `reports/port-business-rl-champion-v3.md`。

完整训练数据、两级课程和五个冠军种子策略保留在 `.runtime/port-business-rl-v3/`，报告保存数据指纹、源码指纹、全部候选摘要和冠军权重。公开发布报告保留权重与指标，但 `.runtime` 大体积数据由确定性生成器复现，不作为现场数据发布。

## 非强化学习补齐

- 需求预测：训练段岭回归时序模型，验证 WAPE 4.9887%，封存测试 WAPE 4.2190%，均优于同月周期朴素基线。
- 可行排程：确定性枚举器执行资源守恒、动作成本和安全约束，既是对照也是证据不足时的后备。
- 安全与权威：规则动作投影、生产授权门禁、船舶交通安全评估、人工批准、回执和回滚继续独立于强化学习。

## 运行与接口

```bash
node --experimental-strip-types --experimental-specifier-resolution=node scripts/rl/runPortBusinessChampion.ts
node --experimental-strip-types --experimental-specifier-resolution=node scripts/rl/verifyPortBusinessChampion.ts
```

- `GET /api/rl/business/status`：返回合同数量、数据指纹、冠军门禁和生产边界；
- `POST /api/rl/business/project`：对一条 v3 业务记录、动态状态和候选动作执行规则投影与确定性后备评估；只返回建议，不发生产回执。
